# 통합 테스트 시나리오

실제 로컬 인프라(BE, MySQL, Redis, MinIO, MailHog)에 붙여서 브라우저로 확인하는 시나리오다.
`/qa-scenario` 스킬이 이 문서를 읽고 ego lite 로 실행한다. 사람이 직접 따라 해도 된다.

Playwright E2E(`react-boilerplate/e2e/`)와의 차이:

| 구분 | Playwright E2E | 이 시나리오 |
|------|----------------|-------------|
| 백엔드 | MSW 목업 | 실제 BE 와 인프라 |
| 실행 | CI 가 매번 자동 | 필요할 때 에이전트가 실행 |
| 확인 범위 | 화면 동작 | 화면 + DB, Redis, 메일, 파일 저장소 부수 효과 + 화면 이상 여부 |

자주 실행해도 결과가 안정적인 시나리오는 Playwright 로 옮기는 것을 검토한다.

## 공통 규칙

- **사전 조건:** `qa.sh preflight` 가 모두 통과해야 한다. FE 는 MSW 를 끈 상태(`VITE_ENABLE_MSW=false`)여야 한다.
- **테스트 계정:** 반드시 `qa-` 로 시작하는 주소를 쓴다 (예: `qa-todo-1730600000@example.com`). 실행마다 시각을 붙여 겹치지 않게 한다. 샘플 계정(user1, user2, admin)으로 로그인하지 않는다. 로그인하면 그 계정의 기존 세션이 끊긴다.
- **비밀번호:** `Qa12345!x` (테스트 전용, 8자 이상)
- **계정 준비:** 화면 가입 흐름을 검증하는 시나리오가 아니면 `qa.sh create-user <email> <pw> [ADMIN]` 으로 인증까지 끝난 계정을 만든다.
- **정리:** 모든 시나리오가 끝나면 `qa.sh cleanup` 으로 `qa-` 계정과 그 할 일, Refresh Token 을 지운다.
- **증거:** 실패하면 스크린샷과 응답 헤더 `X-Trace-Id` 를 남긴다. traceId 로 BE 로그에서 해당 요청을 찾는다.
- **도구:** `.claude/skills/qa-scenario/scripts/qa.sh` (이하 `qa.sh`). 명령 목록은 인자 없이 실행하면 나온다.

## QA-AUTH-01 회원가입과 이메일 인증

화면 가입부터 메일 링크 인증, 자동 로그인까지 이어지는지 확인한다.

**단계**
1. `/register` 에서 이메일 `qa-signup-<시각>@example.com`, 이름 `QA`, 비밀번호에 테스트 비밀번호를 넣고 "회원가입"을 누른다.
2. `/verify-email?email=...` 로 이동하고 "받은편지함에서 링크를 클릭해 인증을 완료해주세요." 안내가 보이는지 확인한다.
3. `qa.sh mail-link <email> verify` 로 인증 링크를 얻어 같은 페이지에서 연다.
4. 인증이 끝나면 `/todos` 로 이동하고 상단 바에 가입한 이메일이 보이는지 확인한다.

**기대 결과**
- 2번에서 오류 문구 없이 안내가 보인다.
- 4번에서 "인증 실패" 같은 오류 화면이 잠깐이라도 남지 않고 `/todos` 로 간다.

**부수 효과**
- `qa.sh sql "SELECT email_verified FROM member WHERE email='<email>'"` 가 `1`
- `qa.sh mail-count <email>` 가 `1` (인증 메일 한 통)
- 같은 링크를 다시 열면 "인증 링크가 만료되었거나 유효하지 않습니다." 가 보인다 (토큰 1회용).

## QA-AUTH-02 로그인 실패와 성공

**사전 조건:** `qa.sh create-user qa-login-<시각>@example.com <pw>`

**단계**
1. `/` 에서 아무것도 넣지 않고 "로그인"을 누른다.
2. 존재하지 않는 이메일 `qa-nobody-<시각>@example.com` 과 아무 비밀번호로 로그인한다.
3. 준비한 계정 이메일에 틀린 비밀번호로 로그인한다.
4. 올바른 비밀번호로 로그인한다.

**기대 결과**
- 1번: 입력칸 아래에 "이메일을 입력해주세요.", "비밀번호를 입력해주세요." 가 보이고 요청이 나가지 않는다.
- 2번과 3번: 둘 다 "이메일 또는 비밀번호가 올바르지 않습니다." 로 같은 문구다 (가입 여부를 드러내지 않음).
- 4번: `/todos` 로 이동하고 상단 바에 이메일과 "로그아웃" 버튼이 보인다.

**부수 효과**
- 로그인 후 `qa.sh redis TTL APP:AUTH:REFRESH_TOKEN:<회원 번호>` 가 1800 이하의 양수 (미활동 만료 30분)

## QA-AUTH-03 로그아웃 후 Access Token 차단

**사전 조건:** `qa.sh create-user qa-logout-<시각>@example.com <pw>` 후 화면에서 로그인

**단계**
1. 로그인 상태에서 `page.evaluate` 로 localStorage `user-store` 의 accessToken 을 읽어 둔다.
2. 상단 바의 "로그아웃"을 누른다.
3. 읽어 둔 토큰으로 `qa.sh api GET /todos <token>` 을 호출한다.

**기대 결과**
- 2번 후 로그인 화면으로 돌아간다.
- 3번이 `401` 과 `AUTH_UNAUTHORIZED` 를 돌려준다.

**부수 효과**
- `qa.sh redis EXISTS APP:AUTH:REFRESH_TOKEN:<회원 번호>` 가 `0`
- `qa.sh redis KEYS 'APP:AUTH:ACCESS_TOKEN_DENY:*'` 에 키가 하나 이상 있다.

## QA-AUTH-04 비밀번호 재설정

**사전 조건:** `qa.sh create-user qa-reset-<시각>@example.com <pw>`

**단계**
1. 로그인 화면에서 "비밀번호를 잊으셨나요?"로 이동해 준비한 이메일로 "재설정 메일 발송"을 누른다.
2. "비밀번호 재설정 메일을 발송했습니다" 안내를 확인한다.
3. `qa.sh mail-link <email> reset` 으로 링크를 얻어 연다.
4. 새 비밀번호 `Qa67890!y` 를 두 칸에 넣고 "비밀번호 변경"을 누른다.
5. 새 비밀번호로 로그인하고, 예전 비밀번호로는 로그인이 실패하는지 확인한다.

**기대 결과**
- 3번 링크가 "새 비밀번호 설정" 화면을 연다 (404 화면이 아니어야 함).
- 4번 후 "비밀번호가 성공적으로 변경되었습니다." 가 보인다.
- 5번 결과가 기대와 같다.

**추가 확인**
- 가입되지 않은 `qa-nobody-<시각>@example.com` 으로 요청해도 같은 안내가 보이고 메일은 오지 않는다 (`mail-count` 가 `0`).

## QA-TODO-01 할 일 추가, 완료, 필터, 삭제

**사전 조건:** `qa.sh create-user qa-todo-<시각>@example.com <pw>` 후 로그인

**단계**
1. 빈 목록 안내가 보이는지 확인한다.
2. "QA 할 일 A", "QA 할 일 B" 를 차례로 추가한다.
3. "QA 할 일 A" 의 체크박스를 눌러 완료한다.
4. "완료" 탭에는 A 만, "미완료" 탭에는 B 만 보이는지 확인한다.
5. "전체" 탭으로 돌아와 새로고침한 뒤에도 상태가 유지되는지 확인한다.
6. B 의 "삭제"를 누르고 확인 창에서 "삭제"를 누른다.

**기대 결과**
- 각 단계의 화면이 기대와 같고, 새로고침 후에도 A 는 완료 상태로 남는다 (목록 캐시가 변경 후 갱신됨).

**부수 효과**
- `qa.sh sql "SELECT title, completed, deleted_at IS NOT NULL FROM todo t JOIN member m ON m.id=t.member_id WHERE m.email='<email>' ORDER BY t.id"` 결과가 `A 1 0`, `B 0 1` (B 는 논리 삭제)

## QA-ADMIN-01 관리자 메뉴와 권한

**사전 조건:** 일반 계정 `qa-user-<시각>@example.com`, 관리자 계정 `qa-admin-<시각>@example.com` (`create-user ... ADMIN`)

**단계**
1. 일반 계정으로 로그인해 상단 메뉴를 확인하고, 주소창으로 `/admin` 에 들어가 본다.
2. 일반 계정 토큰으로 `qa.sh api GET /admin/members <token>` 을 호출한다.
3. 로그아웃 후 관리자 계정으로 로그인해 상단 메뉴의 "관리자"를 누른다.

**기대 결과**
- 1번: "관리자" 메뉴가 없고, `/admin` 진입이 막힌다 (다른 화면으로 이동).
- 2번: `403` 과 `PERMISSION_FORBIDDEN` (화면 가드와 별개로 BE 가 막는지 확인)
- 3번: "관리자" 메뉴가 보이고 "관리자 전용 영역입니다." 화면이 열린다.

## QA-AUTH-05 로그인 요청 횟수 제한

같은 IP 와 경로로 1분에 10번을 넘으면 429 가 난다. 실행 후 1분 동안 이 PC 의 로그인이 막히므로 **항상 마지막에 실행한다.**

**단계**
1. 로그인 화면에서 `qa-ratelimit-<시각>@example.com` 과 틀린 비밀번호로 11번 연속 로그인한다.

**기대 결과**
- 11번째에 로그인 버튼이 "N초 후 재시도" 로 바뀌고 비활성화된다.
- 전역 오류 토스트가 함께 뜨지 않는다 (화면이 직접 안내).

**부수 효과**
- `qa.sh redis KEYS 'APP:RATE_LIMIT:*'` 에 콜론이 밑줄로 바뀐 IP 키가 있다 (예: `APP:RATE_LIMIT:0_0_0_0_0_0_0_1:/api/auth/login`).

## QA-SESSION-01 세션 미활동 만료

기본 미활동 만료는 30분이라 그대로는 확인할 수 없다. 시간을 줄여 BE 를 따로 띄워야 하므로 `all` 실행에서 제외한다.

**준비 (사람이 직접, 또는 지정 실행 시 스킬이)**
- 미활동 40초, Access Token 15초로 BE 를 띄운다. FE 도 이 BE 를 가리키게 띄운다 (스킬 문서의 "다른 포트의 서버를 대상으로 실행할 때").

```bash
./gradlew bootRun --args='--server.port=9095 --spring.profiles.active=local --cors.allowed-origins=http://localhost:5174 --jwt.session-idle-timeout-ms=40000 --jwt.access-token-validity-ms=15000'
```

**단계**
1. 로그인한 뒤 45초 동안 아무 요청도 하지 않는다.
2. 할 일 추가와 필터 탭 클릭을 연달아 한다 (여러 요청이 동시에 실패하는 상황).
3. 다시 로그인하고, 10초마다 필터 탭을 눌러 요청을 보내며 60초 이상 지낸다.

**기대 결과**
- 2번: "세션이 만료되었습니다. 다시 로그인해주세요." 안내가 **한 번만** 뜨고 로그인 화면으로 이동한다. 다른 오류 토스트가 함께 쌓이지 않는다.
- 2번 후 localStorage `user-store` 의 토큰이 비어 있다.
- 3번: 60초가 지나도 로그인이 유지된다 (활동 중에는 재발급할 때마다 미활동 만료가 연장됨).

**부수 효과**
- 3번 중 `qa.sh redis TTL APP:AUTH:REFRESH_TOKEN:<회원 번호>` 가 40 이하의 양수로 계속 다시 늘어난다.
